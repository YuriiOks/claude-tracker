How it works

The first request for a given bucket key seeds a counter in Redis with a TTL window. Each subsequent request increments the counter; when it crosses the limit, the gateway returns 429 with a Retry-After hint.

The bucket key is composed of {api_version}:{user_id}:{route} — note the API version prefix.

Gotchas

  • Bucket key includes the API version — rotating it resets every counter.
  • Retry-After is best-effort; clients should still back off exponentially.
  • Burst allowance only applies on cold start, not after a 429.
