claude-tracker — Docker setup

Local stack on uncommon ports 47820 47821 — Python 3.13 backend, Node 22 / Vite 8 frontend, all deps pinned. The backend mounts your ~/.claude directory read-only and watches it for live activity.

First-time bootstrap

# 1. Create your local docker env file
cp .env.docker.example .env.docker
# Edit REPO_ROOTS (CONTAINER paths under /host/home/...)

# 2. Build and start the stack
make docker-up

# 3. Seed the SQLite cache from your real Claude session history
make docker-ingest

# 4. Open the app
open http://localhost:47820
One-time only. After the first docker-up, both containers restart on Docker Desktop boot via restart: unless-stopped. Use make docker-down to stop, make docker-logs to tail.

Volume strategy

~/.claude → /host/.clauderead-only

Source of truth for live activity. The watcher tails projects/**/*.jsonl as you use Claude Code. Read-only so the container can't accidentally clobber your session history.

${HOME} → /host/homeread-only

Bind-mount of your home directory. Lets the repo scanner walk <repo>/.claude/ folders and run git symbolic-ref for branch detection. Narrow to a parent like ${HOME}/Documents if you prefer in .env.docker.

tracker-cache → /app/.cachenamed volume

Persistent SQLite at /app/.cache/tracker.db plus JSONL byte offsets for the tail watcher. Survives docker-down; nuked by docker-prune.

./src etc. → /app/...read-only mount

Frontend source files are bind-mounted into the dev container so Vite HMR sees host edits instantly. node_modules stays in the container layer for speed.

Gotchas

REPO_ROOTS uses container paths. Inside the container your repos live under /host/home/..., not /Users/you/.... The example file shows the translation. Forgetting this is the #1 way the dashboard ends up empty.
watchfiles + macOS bind mounts. macOS doesn't deliver inotify across the Docker boundary reliably. The watcher polls as a fallback — fine for our single-user case, but if live updates lag more than ~2 s, switch to running bare metal (make dev) for that session.
Non-root container, host-owned files. The backend runs as tracker uid inside the container. Volumes are :ro so this doesn't matter, but if you ever switch to :rw you'll hit perms. Don't switch.

Bare-metal still works

Nothing about Docker breaks the bare-metal path. make dev still launches the venv'd backend on :8765 and Vite on :5173. Same code, same env contract, just no containers.

# bare metal
make install          # uv sync + npm install
make ingest
make dev              # → http://localhost:5173

# docker
make docker-up
make docker-ingest
open http://localhost:47820
