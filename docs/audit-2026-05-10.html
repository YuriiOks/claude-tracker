Design System Violations — Critical

F1 — Design System
#00ff88 live-green is not a CSS token
Impact The live-green color is hardcoded in 6 places across 3 files. Any future brand change requires a grep-and-replace across components rather than a single token edit. The value also cannot participate in the dual-theme system while hardcoded.

styles.css defines --green for the pulseLive glow animation but has no --live token for the bright #00ff88 indicator used wherever an active session is shown.

FileLine(s)Context
src/components/Sidebar.jsx L59 Live badge: color: '#00ff88', rgba(0,255,136,.15)
src/components/Sidebar.jsx L77 Repo dot: --accent: r.isActive ? '#00ff88' : r.accent
src/components/Repos.jsx L13–14 LIVE_BADGE_STYLE — .rb-live background + color
src/components/Repos.jsx L27, L30 LIVE_BADGE_STYLE — .rb-now border + bold color
src/components/Repos.jsx L40 RepoCard: --accent: repo.isActive ? '#00ff88' : repo.accent
src/components/Repos.jsx L102 RepoListRow: same active-accent pattern

Fix applied: Added --live: #00ff88; to both [data-theme="dark"] and [data-theme="light"] blocks in src/styles.css. Replaced all hardcoded occurrences with var(--live) and rgba(from var(--live) r g b / 0.12) for the alpha variant. The value is identical in both themes — live green is a fixed brand signal regardless of theme.

F2 — Design System
Injected <style> tags inside component renders
Impact With 5 repos in grid view, LIVE_BADGE_STYLE inside RepoCard injects 5 identical <style> blocks into the DOM on every render. Beyond the DOM bloat, the styles live outside the token system and cannot reference var(--live), var(--brd), or any theme variable.
  • src/components/Repos.jsx L36: <style>{LIVE_BADGE_STYLE}</style> inside RepoCard — repeated once per card in grid view.
  • src/components/LiveAgents.jsx L126: <style>{STYLES}</style> in the LiveAgents component root.

Fix applied: Both LIVE_BADGE_STYLE and STYLES are static CSS. They were moved to src/styles.css, eliminating repeated injection and allowing all rules to reference design tokens.

F3 — Design System / Dual-Theme Bug
--bord typo — dark navy borders in light mode
Impact In light mode, --bord is undefined, so borders on .la-row and .la-empty fall back to the dark navy hardcoded value, appearing visually dark on the cream background. In dark mode the fallback is close enough to the real value that the bug is invisible, which delayed detection.

The correct design token is --brd. The STYLES constant in LiveAgents.jsx used --bord with a dark-navy fallback:

/* Before — in STYLES constant (LiveAgents.jsx) */
border: 1px solid var(--bord, #2a2f3a);   /* L26 — .la-row  */
border: 1px dashed var(--bord, #2a2f3a);  /* L74 — .la-empty */

Fix applied: Replaced var(--bord, #2a2f3a) with var(--brd) in both locations (no fallback needed once the rule lives in styles.css where the token is defined).

F4 — Design System — Documented exemption
TweaksPanel always renders in light palette
Status: documented exemption (intentional design) User confirmed the always-light palette is intentional — the TweaksPanel reads as a floating macOS-style control sheet, not part of the dashboard chrome. The exemption is now recorded in .claude/rules/dual-theme.md so future readers don’t try to “fix” it.

Lines 3–38 of TweaksPanel.jsx hardcode a warm-cream + dark-text palette:

background: rgba(250,249,247,.78); color: #29261b;

These values never respond to data-theme="dark". In dark mode the panel floats as a lit card over the dark dashboard.

Resolution: Option A — intentional design. A new Documented exemptions section was added to .claude/rules/dual-theme.md with a table row for TweaksPanel explaining the always-light rationale. No code changes were needed.

Code Logic — Medium

F5 — React
Math.random() without useMemo in AgentDetail
Impact The callsToday metric regenerates on every parent-triggered re-render. The value visibly changes when navigating or toggling the theme — a subtle flicker that undermines the metric's credibility.

The call was in the component body at AgentDetail.jsx L13:

callsToday: Math.floor(Math.random() * 18) + 2,

Fix applied:

const defaultCallsToday = useMemo(
  () => Math.floor(Math.random() * 18) + 2,
  [name]
);
const meta = (AGENT_META && AGENT_META[name]) || {
  ...
  callsToday: defaultCallsToday,
};

The [name] dependency reseeds the value only when the selected agent changes, which is the intended behavior.

F6 — React
Array-index key in dynamic filtered list (Pages.jsx)
Impact When the search query changes, items shift position in the filtered array. With key={i}, React reuses DOM nodes by position rather than identity — causing wrong transitions and potentially rendering stale content for the wrong item.

AgentsPage in Pages.jsx L99:

{/* Before */}
{filtered.map((x, i) => (
  <div key={i} className="cd clickable" ...>

Fix applied:

{filtered.map((x) => (
  <div key={x.kind + '-' + x.name} className="cd clickable" ...>

The compound key is stable and unique: the same name cannot appear as both agent and skill in a single result set.

F7 — Design System / Dual-Theme
.la-count hardcoded blue tint
Impact The session-count pill shows a blue tint on the cream background in light mode instead of the expected amber accent.

STYLES L85 in LiveAgents.jsx:

background: rgba(108, 208, 255, .12);  /* hardcoded blue */

Fix applied: Changed to background: var(--dim). The --dim token is dual-themed: rgba(6,182,212,.12) in dark mode (cyan tint), rgba(217,119,6,.10) in light mode (amber tint).

Backend — Medium

B1 — Python / FastAPI
get_repo() does O(n) disk scan for a single-repo lookup
Impact scan_all_repos() walks every configured repo directory on disk before returning. The early return inside the loop does not help — all scans complete before the iterator is consumed.

Before, in backend/app/routers/repos.py:

async def get_repo(repo_id: str) -> Repo:
    for repo in scan_all_repos():   # walks ALL repo directories
        if repo.id == repo_id:
            return repo

Because id = repo_path.name (see repo_scanner.py L84), the repo can be located directly by directory name without scanning siblings.

Fix applied: Added get_repo_by_id() helper to repo_scanner.py:

# repo_scanner.py — new helper
def get_repo_by_id(repo_id: str) -> Repo | None:
    settings = get_settings()
    for i, repo_path in enumerate(settings.repo_paths):
        if repo_path.name == repo_id:
            return _scan_one(repo_path, ACCENTS[i % len(ACCENTS)])
    return None

# repos.py — updated endpoint
async def get_repo(repo_id: str) -> Repo:
    repo = get_repo_by_id(repo_id)
    if repo is None:
        raise HTTPException(status_code=404, detail=f"repo not found: {repo_id}")
    return repo
