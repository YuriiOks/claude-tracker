THE CHALLENGE

English callers get a broken experience

When an English-speaking caller reaches a DE/FR phonebot, the system has no way to switch — garbled ASR, wrong voice, frustrated drop-offs. We evaluated 3 approaches:

Option A: Prompt-Only

Add "respond in English" instruction to the system prompt. Zero infra changes.

Option B: Multilingual

Set Retell's language: "multi" for auto-detection. One config change.

Option C: Agent Transfer

Swap mid-call to a separate EN-configured Retell agent. Native voice + ASR.

OPTION A

Prompt-Only Override

Add "Respond in English from now on" to the system prompt when the caller asks. The simplest possible approach.

✓ Pros

▸ Zero infrastructure changes

▸ Instant to implement (~30 min)

▸ No new agents or Retell config

▸ Works with current architecture as-is

✗ Cons

▸ Same DE/FR voice speaks English — heavy accent, unnatural

▸ Same DE/FR ASR transcribes English — "I need a lawyer" → "Ei nied ä lohja"

▸ No bidirectional switch possible

▸ Entity extraction degrades on garbled transcripts

Verdict: Band-aid solution. LLM output is English but the voice and ears are still German. Caller experience is barely improved.
OPTION B

Multilingual Mode

Set Retell agent's language: "multi" — ASR auto-detects the spoken language. One config toggle in the Retell dashboard.

✓ Pros

▸ Better ASR — auto-detect handles English input

▸ Single config change in Retell dashboard

▸ No backend or voice service changes needed

▸ Some language detection out of the box

✗ Cons

▸ Same DE/FR voice model — German accent speaking English

▸ One-way only — can't switch back to DE/FR once in multi mode

▸ ASR auto-detect inconsistent — may misidentify short phrases

▸ No control over when/how the switch happens

Verdict: Better ASR, but the voice is still German. One-way only kills bidirectional. No explicit caller confirmation flow possible.
OPTION C

Agent Transfer

Retell's agent_transfer tool swaps to a separate EN-configured agent mid-call. Separate voice, separate ASR, same Custom LLM WebSocket.

✓ Pros

▸ Native EN voice — separate 11labs English TTS

▸ Native EN ASR — en-US transcription, no garbled text

▸ Bidirectional — DE↔EN, FR↔EN, switch back anytime

▸ State preserved via Redis (same pattern as call forwarding)

▸ Same Custom LLM endpoint — JupusAgent logic unchanged

⚠ Tradeoffs

▸ Requires 3 agents per environment (DE, FR, EN × 3 envs)

▸ Backend model change (PhoneNumber → M2M additional agents)

▸ Admin UI work for multi-agent phone number config

▸ ~22h implementation vs ~0.5h for prompt-only

Key insight (pending verification): Agent Transfer should work with Custom LLM WebSocket agents — both source and destination point to the same endpoint. Requires confirmation from Retell support before implementation begins.

THE PROBLEM

Failed forwards → callers feel dismissed

When forwarding triggers and the human doesn't answer, the system immediately reconnects the caller to the AI. From the caller's perspective: "I was told 'I'll connect you' and instantly got the robot back." This creates distrust — especially during business hours.

▸ Perceived as dismissive

→ After

▸ No answer → voice prompt: "Wait or continue?"

▸ Caller CHOOSES → feels in control

▸ Professional experience
